Using filamentum with an AI agent

An AI coding agent such as Claude Code can run filamentum’s jobs in a RELION project: add the External jobs with relion_pipeliner, read the statistics and propose selection limits. filamentum ships a guide for such agents. Write it into the RELION project folder, where Claude Code reads CLAUDE.md at the start of a session:

cd /path/to/relion/project
filamentum agent-guide --o CLAUDE.md            # or --append to add it to an existing CLAUDE.md

The guide sets ground rules (work through the pipeline, back up default_pipeline.star, ask before using GPUs or deleting anything, report numbers from the job files), lists the jobs and their options, gives the relion_pipeliner commands, and explains how to read the outputs and choose selection limits. Edit the copy for your site, e.g. with queue names and submission templates.

The guide:

# filamentum in this RELION project: guide for AI agents

filamentum traces filaments in cryo-EM micrographs and writes RELION coordinates. It runs as RELION `External` jobs. This file
tells an agent (e.g. Claude Code) working in this RELION project how to use it. Written by `filamentum agent-guide`; the options of
each command are in `filamentum COMMAND --help`, and the full documentation is at https://folab-liu.github.io/filamentum-docs/.

## Ground rules

- Work through the RELION pipeline: add jobs with `relion_pipeliner` (or ask the user to use the GUI), so every result is a job with
  inputs, outputs and a record. Do not write into another job's folder, and do not edit `default_pipeline.star` by hand.
- Back up `default_pipeline.star` before adding jobs, and do not add jobs while another process (the GUI, a running pipeliner) is
  adding jobs to the same project.
- A job may only take inputs from jobs that already exist. Give each job a short alias that says what it is (e.g. `TrainPili`,
  `TraceAll`, `SelLen1`).
- Changed particle or coordinate STAR files go into the pipeline as External jobs (with RELION_OUTPUT_NODES.star), never through
  Import.
- Ask before using GPU or long-running resources, and before deleting or overwriting anything. Do not cancel running jobs you did
  not start.
- Report numbers from the files (run.out, progress.tsv, micrograph_stats.txt, val_scores.tsv), not from memory, and say which job
  they came from.

## The jobs

All are External jobs. RELION calls `<executable> --o External/jobNNN/ [--in_mics F] [--in_coords F] [--in_parts F]
[--<param label> <value> ...] --j <threads> <other arguments>`. Each writes RELION_JOB_EXIT_SUCCESS/FAILURE/ABORTED and
RELION_OUTPUT_NODES.star; `run.out` ends with a `finished:` line.

| step | executable | inputs | params / other arguments | main outputs |
|---|---|---|---|---|
| fine-tune | `filamentum-train-relion` | `in_coords` = `ManualPick/jobNNN/manualpick.star` (start-end picks) | `--init pan` (default) / `none` / a model.pt; `--iters 3000` | `model.pt`, `val_scores.tsv` |
| trace | `filamentum-trace-relion` | `in_mic` = micrographs STAR with optics table | param `ckpt` = model.pt (default: shipped pan network); `--max N --qc N` for a test | `relion_lines/lines.star`, `relion_straight/startend.star`, `progress.tsv`, `logfile.pdf` |
| select | `filamentum-select-relion` | `in_mic` = micrographs to select from (optional) | params `tracer_job`, `min`, `max` (`stat=value[,stat=value]`), `coords` (`no` to skip lists) | `micrographs.star`, `micrograph_stats.tsv`, coordinate lists of kept micrographs |
| annotate | `filamentum-annotate-relion` | `in_part` = particles | param `tracer_job` (traced with `--save_maps`) | `particles.star` with `rlnFtr*` columns |

Adding and running a job from the project folder (RELION environment loaded):

```
relion_pipeliner --addJob External --setJobAlias TraceTest --addJobOptions "fn_exe == filamentum-trace-relion;in_mic == CtfFind/job003/micrographs_ctf.star;param1_label == ckpt;param1_value == External/job006/model.pt;nr_threads == 16;other_args == --max 50 --qc 10;"
relion_pipeliner --RunJobs "External/job007/"
```

Job option names are those of an External job's job.star: `fn_exe`, `in_mic`, `in_coords`, `in_part`, `param1_label` ...
`param10_value`, `nr_threads`, `other_args`, and for a queue `do_queue == Yes;qsubscript == <template>;qsub == sbatch;`. Never
give an option with an empty value; leave it out. Check the new job number in `default_pipeline.star` before running it.

## Recommended sequence

1. The user picks 3-10 micrographs in Manual picking (start-end mode), annotating every filament on each picked micrograph.
2. Fine-tune on a GPU. Read `val_scores.tsv` and the `kept step` line of run.out; step 0 means the starting network was kept.
3. Trace a sample: `--max 100 --qc 20`. Show the user `qc/*.png` and `logfile.pdf`; compare settings with further QC jobs on
   the same micrographs (`qc/compare/`).
4. Trace everything (same job without `--max`). Many CPU cores help most: tracing, not the GPU, sets the speed.
5. Select micrographs from the statistics, then let the user check the selection: in the select job's outputs, the coordinate
   list opens the kept micrographs in RELION's manual picker (Display).
6. Extract with the select job's `micrographs.star` and a coordinate list (`relion_lines/lines.star` for RELION 5.1 curved
   extraction, `relion_straight/startend.star` otherwise).

## Reading the outputs

- `progress.tsv`: one row per traced micrograph: `n_traces`, `length_um`, `straight_pieces`, `straight_kept_um`,
  `straight_dropped_um`, `median_trace_nm`, `max_trace_nm`, `n_crossings`, `length_per_um2`, `crossings_per_um`.
- `micrograph_stats.txt`: percentiles of each statistic; `logfile.pdf`: histograms and scatter plots with Spearman correlations.
- `failed.txt`: micrographs that could not be read or traced. `filament_trace_params.txt`: every option, the code version and the
  network checksum (cite these when reporting a run).
- `select` job: `micrograph_stats.tsv` has a `selected` column and `left_out_because` for every micrograph.

## Choosing selection limits

- Base limits on the tracing job's distributions, and state what fraction of micrographs a limit keeps before proposing it.
- `n_traces` and `length_um` are nearly the same information. Traced length and crowding go together with crossings per um, so a
  lower limit on `length_um` keeps crowded micrographs unless paired with an upper limit on `crossings_per_um`.
- `min n_traces=1` drops micrographs with nothing traced. The statistics only see exported traces: traces shorter than
  `--min_trace_nm` (25 nm) are not counted, so such micrographs look empty.

## Units and options

Lengths in nm (`*_nm`), areas in nm2, angles in degrees (`*_deg`); pixel size, box and particle sizes in A as in RELION. Common
tracing options: `--border_nm` (10), `--min_trace_nm` (25), `--avoid_crossings_nm R` (off), `--thresh` (0.5), `--spline_nm` (30),
`--sample_step_nm` (5), `--min_piece_nm` (40, straight export only), `--no-span` (skeleton tracer). `--resume` continues an
interrupted run in the same folder.

## Pitfalls

- The number RELION's manual picker shows for a lines list is the number of control points, not the length or the number of traces.
- The progress line can show 0 traced for minutes: tracing processes finish in waves. Do not conclude the job is stuck before
  several minutes without a new line.
- Do not compare traced lengths between runs with different `--border_nm`, `--min_trace_nm` or `--avoid_crossings_nm` without
  saying so.
- With very few picks, fine-tuning often keeps the starting network (step 0); that is the intended safeguard, not a failure.
